# Third-party notices

`cgmr` ships **8 direct dependencies**, which pull in 23 crates in total
on the four platforms it supports (Linux and macOS, x86_64 and aarch64).
This file says why each direct one is there rather than hand-rolled, which
part of cgmr may use it, and what licence the set carries.

## Why each direct dependency is there

Each crate is reached through one facade node, never from domain code
(`SPEC.md` constraints). Anything else that would enter the graph needs a
row here first, with its reason.

| Crate | Owner | Why not hand-rolled |
| --- | --- | --- |
| [`clap`](https://crates.io/crates/clap) | `src/cli` | Argument parsing, help and usage errors for a few dozen switches. Default features off, so no colour or terminal-size code; cgmr's own colour follows `NO_COLOR`. |
| [`clap_complete`](https://crates.io/crates/clap_complete) | `src/cli` | `cgmr completions <shell>` writes shell completions from the same clap definition, so they cannot drift from the switches. |
| [`clap_mangen`](https://crates.io/crates/clap_mangen) | `src/cli` | `cgmr man` writes the man page from the same clap definition. |
| [`libc`](https://crates.io/crates/libc) | `src/sys` | Raw system calls the safe crates do not wrap: `sysctl`, mach host statistics, `notify`, `dlopen` for NVML, `setiopolicy_np`. |
| [`rustix`](https://crates.io/crates/rustix) | `src/sys` | Safe wrappers for file, `statvfs` and process calls on Linux and macOS, so most system calls need no `unsafe`. Only the `std`, `fs` and `process` features. |
| [`sysinfo`](https://crates.io/crates/sysinfo) | `src/sys` | Load average, memory and the process table, read the same way on both systems. Only the `system` feature. |
| [`objc2-core-foundation`](https://crates.io/crates/objc2-core-foundation) | `src/sys` (macOS) | CoreFoundation types that IOKit answers in: dictionaries, numbers, strings. The version `sysinfo` already pulls, so no new crate. |
| [`objc2-io-kit`](https://crates.io/crates/objc2-io-kit) | `src/sys` (macOS) | Disk statistics, battery, HID idle time and GPU statistics from IOKit. The version `sysinfo` already pulls, so no new crate. |

None of them opens a network connection. The only network use in cgmr is
`--rtt` (a TCP connect to the host you name) and `--host` (your own `ssh`).
The build runs offline from the tracked `Cargo.lock`.

Test-only crates (`assert_cmd`, `predicates`, `proptest`, `tempfile`) are
dev-dependencies: they build the test suite and are never shipped.

Every crate is available under MIT, except that `unicode-ident` (pulled by
clap's derive macros at build time) also carries the Unicode-3.0 licence
for its data tables. `deny.toml` allows exactly those two licences and
`cargo deny` gates every change against it.

The table is a readable copy of what `Cargo.lock` resolves, rendered by
`congestimancer-dev notices` (dev/), and the `notices` step fails when the
two differ.
